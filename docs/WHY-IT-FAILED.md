# 为什么说这是一个失败品

不是客套，是结论。

---

## 一、目标与结果的差距

**原始目标**：从零训练一个「懂 EVE」的模型，能用对话回答问题。

**实际结果**：一个把结构化字段念成通顺中文的模板机器，外面包了一层检索和路由。

| 能力 | 结果 | 说明 |
|---|---:|---|
| 抄写给定字段 | 94% | 唯一真正做到的 |
| 复述装配槽位 | 100% | 同上，本质是抄 |
| 数一个舰种有几艘 | **0%** | 需要计数，做不到 |
| 读一段散文回答「X 是什么」 | **20%** | 做不到 |
| 判断该不该回答 | **10%** | 做不到 |
| 回答「推荐一条刷深渊的船」 | 失败 | 只给原文摘录 |

**裸模型 69.5%，其中一半分数来自「抄」。**

---

## 二、最打脸的一刻

200 道自造题评测拿到 100% 之后，用 7 个真实口语问题去问：

| 问 | 答 |
|---|---|
| 配一条刷四级深渊的船，推荐什么 | 深渊建筑介绍片段 |
| 毒蜥和伊什塔哪个好 | 只给伊什塔属性卡 |
| 新手怎么赚钱快 | 商人攻略碎片 |
| 这游戏怎么玩 | 挂单技巧片段 |
| 多米尼克斯装满多少钱 | **中能量槽是 5 个** |
| 无畏刷怪注意什么 | T2 弹药片段 |
| T3C 是什么船 | 舰队集结通知 |

**7 个全错。**

100% 和 0% 之间没有中间态，因为评测题目是按系统已有能力反向生成的。
这不是「评测不严」，这是**自己给自己出考卷**。

---

## 三、错误的假设

### 假设 1：小模型 + RAG 就能答好

**错在哪**：RAG 解决「不知道事实」，不解决「不会用事实」。

系统能查出正确资料（recall@10 97.7%），但拿到资料之后：

- 不会概括
- 不会比较
- 不会按用户场景筛选
- 不会判断「这个问题资料里其实没有」

**这些全是理解能力，35M 参数没有。**

### 假设 2：护栏能兜住小模型的不足

**部分对**。护栏确实把事实准确率从 69.5% 拉到 100%，但代价是：

- 护栏能做的只有「查表」「比数字」「拒答」——**全是确定性判断**
- 一旦问题需要「组织语言」，护栏就失效了
- 最后系统变成了「一堆 if-else + 一个复读机」

**100% 是工程的胜利，不是模型的胜利。**

### 假设 3：数据够多就能训出理解

**错在哪**：425 万 token 对 35M 参数来说是够的（接近 Chinchilla 配比），
但**理解了「足够」不等于「有能力」**。

计数、摘要、意图识别这些能力，不是数据量的问题，是**模型容量的下限**。
35M 参数就是做不了。

### 假设 4：全参数训练比调用 API 更有价值

**这是最大的一个错。**

省下的 API 成本，被多花的时间全部吃掉：
造语料、写求解器、调训练、修护栏、做评测、抓标签位移的 bug……
而且最终效果还不如调用一个现成 API。

**「必须本地」这个约束本身，可能才是问题的根源。**

## 四、侥幸成立的部分

诚实地说，有几件事做对了：

| 做对的 | 为什么 |
|---|---|
| 事实一律走 SDE，不让模型记忆 | 模型真会编（答 235，真值 3200） |
| 数值闭集校验 | 模型会把 9999 抄成 907 |
| 舰种/词条走查表 | 裸模型 0%，查表 100% |
| 先量检索再优化 | 量完发现 recall@10 97.7%，不是瓶颈，省下了无谓优化 |
| reranker 加了要重测 | 实测更差（78 vs 81.7），果断否决 |

**这些不是「做成了」，是「没有更糟」。**

---

## 五、真正的教训

### 1. 评测集比模型重要

自造题 100%，真实提问 0%。**评测集的价值取决于它有多像真实用户。**

以后任何项目，先收集 50 条真实提问，再动手。

### 2. 小模型的边界要提前划清

35M 能做的：抄、复述、按格式输出。
35M 不能做的：计数、概括、比较、判断。

**这些不是训练能解决的，是选型问题。**

### 3. 「架构」不能弥补「能力」

我花了大量时间设计路由、护栏、查表、兜底——
这些让它从 69.5% 涨到 100%，
但它依然不会回答「推荐一条船」。

**架构决定下限，模型决定上限。**

### 4. 硬件约束会决定项目形态

4 GB 显存 → 35M 参数 → 只能做抄写 → 只能做查询器。

如果当初接受「调用 API」，这个项目三天就能做完，而且效果更好。

**约束值得坚持，但要先算清楚代价。**

---

## 六、如果重来

```
不做：从零训 35M 模型
做：  用现成 embedding + 现成 LLM API + 现在这套结构化数据和护栏

预期：
  事实准确率  ≈ 同样 100%（护栏保证，与模型无关）
  开放问答   ≈ 从「丢原文」变成「真的会回答」
  工期       从 3 周缩短到 3 天
```

**这个仓库真正的价值，是证明了「护栏 + 结构化数据」这条路是对的，
同时证明了「小模型做理解」这条路是错的。**

两条结论都有用，只是第二条更贵。
