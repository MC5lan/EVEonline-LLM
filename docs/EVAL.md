# 评测报告汇总

所有数字都可用仓库内命令复现。评测脚本在 `eval/`。

---

## 1. 端到端评测（200 题）

```bash
python -m eval.run_eval              # 带护栏
python -m eval.run_eval --no-guard   # 只看模型
```

题目从结构化数据反向生成，分六类，标准答案可机械比对。

### 历史演进

| 版本 | 改动 | 总分 |
|---|---|---:|
| baseline | — | 59.5% |
| v2 | 装配判分改为「同船多套都算对」 | 75.5% |
| v3 | 补全 SDE 字段（信号半径/跃迁速度/锁定距离…） | 78.5% |
| v4 | 未知字段拦截 | 87.0% |
| v5 | 舰种/词条走确定性查表 | 93.5% |
| v6–v7 | 查表路由提到最前 | 94.0% |
| v9 | 判分按单位取数（避免把「350mm」的 350 当成答案） | 97.0% |
| v10 | 数值校验改数值比较（1.0 = 1） | 97.0% |
| v12 | **SDE 确定性兜底**（模型写错就换模板） | **100%** |

两次「改坏了」被评测拦住：

| 改动 | 分数变化 | 处置 |
|---|---|---|
| context 只给单个字段 | 94% → 93% | 回退 |
| 被问字段放到末尾 | 94% → 78% | 回退 |

### 当前分数

| 类别 | 题数 | 带护栏 | 裸模型 |
|---|---:|---:|---:|
| fact 事实 | 100 | 100% | 94% |
| fit 装配 | 40 | 100% | 100% |
| class 舰种 | 20 | 100% | 0% |
| lore 剧情 | 20 | 100% | 20% |
| refuse 拒答 | 10 | 100% | 10% |
| guard 字段缺失 | 10 | 100% | 0% |
| **总计** | **200** | **100%** | **69.5%** |

**这 30.5 个百分点的差距全部来自确定性代码**（查表、路由、拒答、数值校验、模板兜底），
不是模型能力。

裸模型真正会的只有两件事：抄写结构化字段（94%）、复述装配槽位（100%）——
恰好是 SFT 数据覆盖的两种模式。

## 2. 检索评测（300 题）

```bash
python -m eval.eval_retrieval --n 300
```

查询从文档正文截取（去掉标题词），标准答案是文档本身。

| 指标 | 数值 |
|---|---:|
| recall@1 | 81.7% |
| recall@3 | 95.0% |
| recall@5 | 96.7% |
| recall@10 | 97.7% |
| MRR | 0.882 |

**结论：检索不是瓶颈。**

### reranker 对照（已否决）

```bash
python -m eval.eval_retrieval --n 300 --rerank
```

| | recall@1 | recall@10 | MRR | 每题耗时 |
|---|---:|---:|---:|---:|
| 基线 | **81.7%** | 97.7% | **0.882** | 21 ms |
| 加重排 | 78.0% | 97.3% | 0.859 | +500 ms |

更慢且更差。模型是 bge-reranker-base（int8，266 MB）。

**注意**：recall@1 的 81.7% 被**版本化文档**低估了。
语料里存在「燃烧单开最速攻略V3 / V3.1 / V3.2」这类同源不同版，
检索命中 V3.1 而标准答案是 V3 时会被判错，但 V3.1 其实也能回答问题。

| 阶段 | 指标 | 值 |
