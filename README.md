## 为什么说它失败了

**这是一个失败品。** 不是「还不够好」，是这条路本身没走通。

| 我原本想要的 | 实际做到的 |
|---|---|
| 一个懂 EVE 的对话助手 | 一个会抄字段的资料查询器 |
| 能回答「推荐一条刷深渊的船」 | 把一段原文丢给你，标一句「未作归纳」 |
| 模型理解 EVE 的内容 | 模型只会把给定的字复述通顺 |
| 端到端 100% 说明效果好 | 100% 只在自己出的 200 道题上，真实提问 **7 个全错** |

**最刺眼的一组对照**：

```
带护栏  100.0%   ← 系统能力，几乎全是确定性代码的功劳
裸模型   69.5%   ← 模型真实水平
裸模型里还只有两件会做：抄字段 94%、列装配 100%
剩下全部不会：计数 0%、剧情概括 20%、判断该不该答 10%
```

一个 35.4M 参数、只见过 425 万 token 的模型，**做不了「理解」这件事**。
它能把「护盾容量 3200 HP」说得像人话，但它不知道这意味着什么。

完整复盘：[docs/WHY-IT-FAILED.md](docs/WHY-IT-FAILED.md)

全部 62 条决策记录：[docs/DECISIONS.md](docs/DECISIONS.md)

## 关于「这是 AI 写出来的」

**这个仓库的全部代码、文档、评测、数据分析，都是 AI agent 跑出来的。**

人做的是：给方向、看结果、否掉错的、说「继续」。
AI 做的是：写代码、造数据、调参、写文档、跑评测、修 bug——包括发现自己写错了标签对齐。

这意味着几件事，看在眼里比较重要：

- **代码风格统一但缺乏「手感」**。很多地方是「按规矩办」而不是「因为这里必须这样」。
- **失败被记录下来了，但不是所有失败都被发现**。100% 的评测是自己造的题，这种自欺欺人的坑，
  agent 会踩，人也会踩。
- **工程量大，洞察少**。18 条踩坑记录是真的，但它们大多是「实现细节踩坑」，
  不是「对 EVE 玩家需求的理解」。

把它当成**「AI 能独立做到什么程度」的一次实测**，比当成一个 EVE 工具更有价值。

## 它到底能干什么

> **定位说明**
> 这是一个**能查资料的助手**，不是顾问。
> 能答：某艘船某个属性多少、某套装配某槽位装什么、某舰种有几艘、某个词条是什么。
> 不能答：帮我推荐一套适合我的配装、新手该怎么规划。
> 后两类会明确返回「以下是原文摘录，未作归纳」，不装懂。

## 2. 架构

```
用户提问
   │
   ├─ 多轮状态机（rag/dialogue.py）──── 指代改写：「那它的中槽呢」→「毒蜥级的中槽装什么」
   │
   ├─ 确定性路由（rag/local_model.py）
   │    ├─ 越界/价格/未知字段 ──────→ 直接拒答，不调模型
   │    ├─ 缩写（T3C/MWD…）───────→ 查表
   │    ├─ 舰种/词条 ────────────→ 查索引文档
   │    ├─ 对比题（A 和 B 哪个好）──→ 并列两者属性，不做判断
   │    ├─ 属性题 ──────────────→ SDE 紧凑 context → 小模型 → 数值校验
   │    ├─ 装配题 ──────────────→ 装配库 slot context → 小模型
   │    └─ 其余 ────────────────→ 结构化摘录（来源 + 最贴题一句）
   │
   └─ 三道护栏
        ├─ 字段缺失检测（调模型之前）
        ├─ 数值闭集校验（生成之后）
        └─ SDE 确定性兜底（模型写错就换模板）
```

**核心分工：模型只负责措辞，不负责事实。**

## 4. 关键设计决策

### 4.1 为什么模型只有 35M

4 GB 显存下，35M 是全参数训练能稳住的规模（batch 2 × 1024 seq，bf16，1.7 GB）。
更大的模型在数据量（4.25M token）下也不划算——Chinchilla 最优配比约 20 token/参数，
我们已经接近，再大就是纯过拟合。

### 4.2 为什么答案要来自结构化数据，而不是模型记忆

实测：让模型凭记忆回答「毒蜥级护盾容量」，它答 **235**（真值 3200）。

35M 参数装不下 4000+ 艘船、4000+ 件装备的数值。所以：

- 数值来自 SDE，SDE 之外一律说不知道
- 模型只做「把给定数字说成通顺中文」
- 模型写错了，`FactContext.lookup()` 用 SDE 的真值覆盖

### 4.3 为什么舰种/词条走查表

裸模型答「无畏舰有几艘」的正确率是 **0%**，答「X 是什么」是 **20%**。
计数和摘要需要的能力远超 35M。这两类答案本来就在我们建的索引里，查表 100% 确定。

### 4.4 为什么不用 reranker（负结果）

下载了 bge-reranker-base（int8，266 MB）做交叉编码器重排：

| | recall@1 | recall@10 | MRR | 每题耗时 |
|---|---:|---:|---:|---:|
| 基线 | **81.7%** | 97.7% | **0.882** | 21 ms |
| 加重排 | 78.0% | 97.3% | 0.859 | +500 ms |

**更慢且更差。** 原因是评测查询取自原文段落，词面重合度本就高，交叉编码器带不来新信息。
代码保留在 `rag/rerank.py`，默认关闭。

### 4.5 为什么评测分数是 100%

因为 200 题是按系统已有能力设计的（事实/装配/舰种/词条/拒答/字段缺失六类），
**不代表真实开放提问的水平**。

真实口语提问（「配一条刷深渊的船」）的正确率远低于此——那类问题在评测里没有覆盖。

## 5. 训练过程

```
预训练  10,200 步 → 停在 3,000 步（val 2.87）
        继续训到 5,000 步 val 升到 3.35，明确过拟合
        数据只有 4.25M token，20 轮就是背下来

SFT     3 轮，10,555 条，val 0.0209
        只对回答算 loss，user 部分标签设 -100
        标签必须右移一位（模型的 loss 不做位移，写错会学成复读）
```

**过拟合的实测表现**：step5000 的模型会流利地背诵训练语料，但答非所问。
35M 模型 + 4.25M token，必须在最优步停下。

## 6. 已知缺陷

| 缺陷 | 现状 |
|---|---|
| 长数字复制不稳 | 9999 会抄成 907 — 由 SDE 兜底覆盖 |
| 上下文 1024 | 长装配答案会被截到 512 |
| 开放提问质量弱 | 只能给原文摘录，不能归纳 |
| 攻略类文档摘句质量一般 | 标题式短句多，挑不出精华 |
| 装配求解器 | 359 套全部通过，但 T3 子系统技能、指挥脉冲波链路未实现 |
| 剧情 | 62 个条目，覆盖 66 个词条中的多数，剩余提及次数过少 |

## 8. 评测记录

```
eval/report_baseline.txt    59.5%   初始
eval/report_v2..v15.txt     75.5% → 100%   逐轮修复
eval/retrieval_baseline.txt recall@1 81.7% / @10 97.7%
eval/retrieval_rerank.txt   78.0%   重排（已否决）
```

分数演进中两次「改坏了」被评测拦住：

- 单字段 context：94% → 93%
- 被问字段后置：94% → 78%

**没有评测，这两个改动会被当成优化留下来。**
