# zh_dev_blog_and_patchnote_no-downtime-on-wednesday-december-4th

===== 首次暫停每日維護測試 =====

原文：https://www.eveonline.com/article/q1wbxb/no-downtime-on-wednesday-december-4th<image shape="circle">譯者 : Rabbit P MuraSaki Siki</image>

每天，CCP 都幻想着今天沒有停機維護多好。

每日例行維護已經不像幾年前需要進行一整個小時，足夠讓我們去吃一個午飯，再吃多一份甜品。今天 Tranquility 在週末的自動重啟只需要大約 4分20秒-4分40秒左右，只夠時間沖一口茶喝。可是依然爲玩家們帶來不便，需要安排好在 11:00 UTC 時停靠在安全地方。

於是，六千多日的歷史後的首次，EVE 將不會於 4/12 週三停機，由 3/12 1100 一直持續運行 5/12 1100。

這將是 CCP 審視對於24時區遊戲玩家們有甚麼能做的一小步。再短的停機維護時間也會對玩家們的體驗造成影響，要使遊戲邁進下一個十年，這問題必需處理。

首先，先退一步回來看一下爲甚麼 EVE 需要停機維護:
- EVE 遊戲運行需要大量內存運作，而一直沒有一個很好的清理內存機制；因爲有每天的停機重啟，CCP 亦並不需要特意去刷新伺服器緩存。
- 每天停機維護時進行日常數據庫作業。
- 有一些事項需要每天處理，因爲每日維護時並沒有玩家在線，是一個非常合適的時間去做這些日常工作。

CCP 已經寫好了一大堆預期會出現的問題，而還有一堆 CCP 並不知道的內容只有通過是次實驗才能得知。

CCP 知道事情一定會有不順暢的地方，例如:小行星帶或會變得非常貧瘠；有一些日常資訊或會沒有正常更新，如物品市場平均價格。甚或，CCP 已經準備好在 4號當天需要進行緊急重啟。到時才知道。

那 CCP 爲甚麼要這樣做? 把停機時間改一下不就好了? 總有一些時間會比現在 1100 更好吧? 事實上，唯一真正的解決方案是沒有停機時間，一切改動停機時間都只是弄虛作假的嘗試。

EVE 玩家們遍佈整個世界，大約可以以三個時區作區分:
- 歐洲，包活西俄及非洲地區
- 與美洲以大西洋分隔
- 美洲
- 與亞洲以太平洋分隔
- 亞洲，包括東俄及大洋洲
- 與歐洲東部的地中海東部/印度洋的西部

=====「太平洋停機時間」=====

從以下圖表型可以看見不同地區的玩家們的上線情況:

看完圖表，第一眼通常都認爲每日維護應該設定在 0700。這稱之爲「太平洋停機時間」，即使在美洲玩家們都下線了而亞洲玩家們還沒上線的時間。先緩一下稍後再跟玩家們解釋這爲甚麼不是最理想的時間。

=====「大西洋停機時間」=====

由CPU 的用量圖表（星系活躍度）上可以看出另一面情況

可以明顯看見有高有低，而這並不是因爲停機維護造成。如果你仔細看一下每一個高峰，都會發現高峰端有一個小低谷。其實這才是每天 1100 的維護時間。每天玩家活躍度都會在 1040 至 1120 下降，這很符合歐洲的午飯時間。EVE 也需要吃飯的。

最低谷出現在 UTC 2330。這即是所謂的 「大西洋停機時間」，歐洲玩家們下線而美洲玩家們還沒上線的時間。
雖然平均活躍度是低，把停機時間定在兩大玩家社區上線時間之間並不是一個好主意。例如，兩個社區的玩家可能會在這一段時間交戰。

而由 CPU 用量上也可以看出來，在午夜及 0700，即使玩家上線人數較少，玩家的活躍度其實相當高。與歐洲玩家相比，美洲玩家的遊玩時間稍長一點。所以「太平洋停機時間」會暫停美洲玩家的遊玩，並不是一個好方法。

=====「地中海停機時間」=====

那地中海時區呢？這應該是最差的答案了，玩家上線人數及活躍度在這時間都相當高。

所有選擇都不合適的話，而無可否認亞洲地區的待遇是較差。

CCP 或許可以把維護時間稍爲推早一點但不能早於0930 UTC。CCP 一直都在審視情況，研究有沒有更好的停機維護時間。

但說實話，搬動維護時間對遊玩體驗並不會有非常大的改進。正如一開始所說，唯一的方法是移除停機維護。

在4/12 將不會進行伺服器停機。儘管如此，CCP 並不是鼓勵玩家在這時段踴躍上線去打破甚麼紀錄。CCP 只想要一個平常的週三。
CCP 希望由是次實驗中獲得數據去審視未來伺服器調整的需求，看看有甚麼要修正，使伺服器能持續運行達48小時，或使每週只需要四次停機。延長運行，減少維護，使問題浮現並針對解決。
